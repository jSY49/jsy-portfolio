## 3. 트러블슈팅 및 기술적 의사결정

### React 버전 충돌 (react-devicons)

- **문제 상황** : React 버전 충돌 (react-devicons)
- **원인 분석** : `npm ls react`로 의존성 트리를 확인해보니 특정 패키지가 다른 React 버전을 내장하고 있어 충돌.
- **해결 방안** : 문제의 라이브러리(react-devicons)를 제거하고, peerDependency 방식이라 버전 충돌 위험이 적은 react-icons로 교체. 이후 새 라이브러리 도입 전
  `npm ls <패키지명>`으로 의존성 트리를 먼저 확인하여 호환성 확인 과정이 필요함.

### Grid 반응형 적용

- **문제 상황** : Grid 반응형 적용에 원하는 방향으로 적용이 되지 않음
- **원인 분석** : 검색으로 찾은 내용을 각 동작 원리를 완전하게 이해하지 못하고 적용해서 결과물만 내려고 한 것이 근본적인 원인이었음. CSS의 레이아웃 배치에 필요한 속성들에 대한 이해가 부족했음.
- **해결 방안** : 구현이 막힌 상태에서 또 다른 정답을 찾기보다는 스스로 정한 개발 원칙을 다시 한번 생각하며 각 속성을 이해 후 적용하는 방법으로 개발을 진행함.

### JSON 파싱 안정성 처리

- **문제 상황** : DB 스키마 형식을 다른 팀원과 동일하게 맞추어둔 상태에서 개인 상황에 따른 속성 값이 필요했고, DB 문자열 속성에 JSON 데이터를 추가하는 방법을 채택.
  이 과정에서 DB에 JSON 문법적 오류가 발생했을 때 바로 웹페이지 로딩이 깨져버림.
- **원인 분석** : JSON을 파싱하는 코드만 추가하고 이와 관련되어 발생할 수 있는 예상 가능한 오류를 처리하지 않았음.
- **해결 방안** : `JSON.parse`를 try/catch로 감싼 안전 파싱 함수를 만들어, 파싱 실패 시 null을 반환하도록 처리. 컴포넌트에서는 null 체크 후 유효한 데이터를 가지고 있는 경우에만 화면을 구성하도록 하여, 하나의 데이터 오류가 전체 페이지 렌더링을 막지 않도록 함.

### SPA 새로고침 시 404 에러

- **문제 상황** : Supabase에서 데이터를 가져오는 프로젝트에서, 루트가 아닌 경로(`/projects` 등)에서 새로고침 했을 때 404 에러 발생.
- **원인 분석** : React Router로 라우팅하는 SPA(Single Page Application)는 서버에 `/about`, `/projects` 같은 실제 파일이 존재하지 않음. 브라우저에서 JavaScript가 URL을 보고 알아서 화면을 바꿔주는 방식이기 때문에, 새로고침 시 서버가 해당 경로의 파일을 찾지 못해 404 오류가 발생함.
- **해결 방안** : `vercel.json`에 rewrite 설정을 추가하여, 정적 파일과 API 요청을 제외한 모든 경로 요청을 `index.html`로 전달하도록 처리함.

```json
{
	"rewrites": [{ "source": "/((?!api/|@)[^.]*)", "destination": "/index.html" }]
}
```

- `(?!api/|@)`: "api/로 시작하지 않고, @로 시작하지 않는"
- `[^.]*`: "점(.)이 없는" 경로 (파일 확장자가 없는 경로만)
- `destination`: 조건에 매칭된 경로를 index.html로 전달, 이후 React Router가 해당 경로를 읽어 알맞은 화면을 렌더링함
<br>=>요청받은 경로가, API 요청도 아니고, 특수 경로(@)도 아니고, 파일 확장자도 없다면 → 이건 React 페이지 라우트니까 index.html로 보내서 React Router한테 맡겨라"
